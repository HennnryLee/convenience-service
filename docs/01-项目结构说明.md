# 便民服务平台 · 项目目录结构说明

> 对应《软件构造》实验一：软件开发概述与项目初始化

## 1. 技术选型

| 层次 | 选型 | 说明 |
| --- | --- | --- |
| 开发语言 | Python 3.12 | 实验要求 3.8+ |
| Web 框架 | Flask 3.1 | 轻量、可插拔，适合增量迭代 |
| 模板引擎 | Jinja2 | 模板继承，减少页面重复代码 |
| ORM | Flask-SQLAlchemy 3.1 | 对象关系映射，隔离数据库差异 |
| 数据库 | SQLite（可切换 MySQL 8.0） | 零配置，便于交付与评阅 |
| 用户认证 | Flask-Login 0.6 | 会话与登录状态管理 |
| 表单处理 | Flask-WTF 1.3 + WTForms | 表单校验 + CSRF 防护 |
| 前端 | HTML/CSS/JavaScript | 自研轻量样式，无 CDN 依赖 |
| 测试 | pytest / pytest-cov / coverage | 单元测试与覆盖率统计 |
| 版本管理 | Git | 增量提交，历史可追溯 |

## 2. 目录结构

```
convenience_service/
├── app/                          # 应用主包（按技术职责分层）
│   ├── __init__.py               # 应用工厂 create_app()
│   ├── config.py                 # 配置（development/testing/production）
│   ├── extensions.py             # 扩展对象 db / login_manager / csrf
│   ├── models/                   # 【数据层】领域模型与 ORM 映射（实验三）
│   ├── repositories/             # 【数据层】数据访问对象，封装 CRUD（实验三）
│   ├── services/                 # 【业务层】业务规则与流程（实验二 TDD 构造）
│   ├── forms/                    # 【表现层】表单与校验规则（实验四）
│   ├── modules/                  # 【表现层】蓝图=业务模块，路由与视图
│   │   ├── main.py               #   首页/门户
│   │   ├── auth.py               #   用户管理：注册、登录、退出、个人信息
│   │   ├── services.py           #   服务查询：搜索、分类浏览、详情
│   │   ├── appointments.py       #   在线预约：选择服务、填写信息、提交
│   │   ├── announcements.py      #   公告资讯：列表、详情、搜索
│   │   ├── feedback.py           #   反馈评价：提交评价、查看历史
│   │   └── admin.py              #   后台管理：服务/用户/预约管理
│   ├── utils/                    # 通用工具：常量表、装饰器、表驱动配置
│   ├── templates/                # Jinja2 模板（base.html 为父模板）
│   └── static/                   # 静态资源 css/js
├── tests/                        # 测试代码（软件测试课程复用同一被测系统）
│   ├── unit/                     #   单元测试（白盒）
│   ├── functional/               #   功能测试（黑盒）
│   ├── integration/              #   集成测试
│   └── system/                   #   系统测试（端到端/安全/性能）

└── requirements.txt              # 依赖清单
```

## 3. 分层与模块化说明

系统按 **表现层（modules/forms/templates） → 业务层（services） → 数据层（repositories/models）** 三层组织：

- **表现层**只负责接收请求、调用业务层、渲染模板，不写业务规则；
- **业务层**承载全部业务规则（如预约容量校验、密码强度、权限判断），可脱离 Web 独立测试；
- **数据层**封装全部 SQL/ORM 操作，业务层不直接写查询条件。

这样做的收益：任何一层的变化都被限制在本层内部（低耦合），
每层内部职责单一（高内聚），且业务层可脱离数据库做单元测试（可测试性）。

## 4. 运行环境

```bash
pip install -r requirements.txt
python run.py --init-db --seed     # 建表并写入演示数据
python run.py                      # 启动，访问 http://127.0.0.1:5000
```
