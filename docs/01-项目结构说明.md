# 便民服务平台 · 项目目录结构说明

> 对应《软件构造》实验一：软件开发概述与项目初始化
> 2026-11-24 工程化改进后更新

## 1. 技术选型

| 层次 | 选型 | 说明 |
| --- | --- | --- |
| 开发语言 | Python 3.10+（实测 3.12） | 实验要求 3.8+；项目声明 3.10+ |
| Web 框架 | Flask 3.1 | 轻量、可插拔，适合增量迭代 |
| 模板引擎 | Jinja2 | 模板继承，减少页面重复代码 |
| ORM | Flask-SQLAlchemy 3.1 | 对象关系映射，隔离数据库差异 |
| 数据库 | SQLite（可切换 MySQL 8.0） | 零配置，便于交付与评阅 |
| 用户认证 | Flask-Login 0.6 | 会话与登录状态管理 |
| 表单处理 | Flask-WTF + WTForms | 表单校验 + CSRF 防护 |
| 前端 | HTML/CSS/JavaScript | 自研轻量样式，无 CDN 依赖 |
| 测试 | pytest / pytest-cov / coverage | 单元、功能、集成、系统四层 |
| 静态检查 | ruff + 自研 `scripts/static_check.py` | 风格/导入/缺陷模式双检查 |
| 持续集成 | GitHub Actions | Python 3.10/3.12 双版本质量门禁 |
| 版本管理 | Git | 增量提交，历史可追溯 |

## 3. 分层与模块化说明

系统按 **表现层（modules/forms/templates） → 应用服务 → 业务规则 → 数据层（repositories/models）** 组织：

- **表现层**只负责接收请求、解析参数、调用服务、渲染模板与 flash，不写业务规则；
- **应用服务**负责一次用例的编排（校验参数、查库、组装结果、给出提示语），
  使视图和业务规则都不依赖具体页面；
- **业务规则层**承载预约容量、时间边界、状态机、密码强度等纯逻辑，可脱离 Web/数据库测试；
- **数据层**封装全部 SQL/ORM 操作，业务层不直接写查询条件。

收益：任何一层的变化被限制在本层内部（低耦合），每层内部职责单一（高内聚），
业务层可脱离数据库做单元测试（可测试性）。2026-11-24 新增的应用服务层
解决了上一版"视图仍承担少量查询"的遗留问题，详见 `docs/09`、`docs/15`。

## 4. 运行环境

```bash
pip install -r requirements.txt
python run.py --init-db --seed     # 建表并写入演示数据（幂等）
python run.py                      # 启动，访问 http://127.0.0.1:5000
```

也可使用 Flask CLI：

```bash
flask --app "app:create_app()" init-db
flask --app "app:create_app()" seed-demo
flask --app "app:create_app()" create-admin boss boss@example.com
flask --app "app:create_app()" check-db
```

默认管理员账号：`admin / Admin@123`；演示用户：`zhangsan / User@123`。
