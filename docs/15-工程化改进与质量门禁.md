# 工程化改进与质量门禁

> 2026-11-24 第二轮重构记录
> 依据：《软件构造》第 5~6 章（静态测试、重构与交付）、《软件质量保证与测试》第 9、11、12 章
> 目标：在不改变对外功能的前提下，让项目结构、运行期质量与测试体系更接近真实工程项目。

## 1. 改进前的问题

| # | 问题 | 影响 |
| --- | --- | --- |
| 1 | 没有统一的质量门禁配置 | 测试/覆盖率/静态检查靠手工命令，CI 无法复现 |
| 2 | 视图层仍直接拼查询、写提示语 | 表现层与业务规则耦合，新增页面容易复制一套逻辑 |
| 3 | 时段字符串在多个函数里各解析一遍 | 时间语义可能两处漂移（开始/结束边界） |
| 4 | 分类导航按分类逐个 COUNT、可评价预约逐条查评价 | N+1 查询，数据量增大后变慢 |
| 5 | 生产环境无日志、5xx 无 request_id | 用户报错后无法定位 |
| 6 | 错误页只覆盖 403/404/500，无统一兜底 | CSRF/405/413 暴露默认错误页 |
| 7 | 会话 Cookie 未显式配置；禁用账号的旧会话仍有效 | 会话安全与权限回收不彻底 |
| 8 | 邮箱大小写、名称首尾空格未规范化 | 可注册大小写变体账号、重名校验被绕过 |
| 9 | 后台编辑服务改名撞库会触发 500 | 用户看到"服务器内部错误"而不是"名称已存在" |
| 10 | 测试集中在正常路径，错误处理/日志/CLI 未覆盖 | 覆盖率数字高，但运维入口没有回归保护 |

## 2. 工程化配置（可执行的质量门禁）

| 文件 | 作用 |
| --- | --- |
| `pyproject.toml` | pytest 分层标记、`--strict-markers/--strict-config`、分支覆盖率 `fail_under=98`、ruff 规则 |
| `requirements-dev.txt` | 在运行依赖上增加 ruff，供本地/CI 共用 |
| `.pre-commit-config.yaml` | 提交前 ruff 快速检查（完整测试交给 CI） |
| `.github/workflows/ci.yml` | Python 3.10/3.12 双版本：ruff → 静态分析 → pytest 分支覆盖率 → 上传报告 |
| `.editorconfig` / `.env.example` / `CHANGELOG.md` | 编码风格、环境变量样例、变更记录 |

本地质量门禁命令：

```bash
python -m ruff check app tests scripts run.py seed.py wsgi.py
python scripts/static_check.py
python -m pytest --cov=app --cov-branch --cov-report=term-missing
```

## 3. 结构调整

```
app/
├── __init__.py          应用工厂（配置校验 → 扩展 → 蓝图 → 登录 → 日志/安全 → 错误页 → CLI）
├── config.py            development / testing / production 配置与安全 Cookie
├── extensions.py        db / login_manager / csrf
├── cli.py               init-db / seed-demo / create-admin / check-db
├── errors.py            400/403/404/405/413/500 与 CSRF 统一错误页 + 5xx 日志
├── logging.py           request_id、访问日志、滚动文件日志
├── security.py          CSP、X-Frame-Options、Referrer-Policy 等安全响应头
├── seed_data.py         幂等演示数据（事务提交/回滚）
├── models/              领域实体
├── repositories/        数据访问（新增聚合计数、NOT EXISTS 查询）
├── services/            纯规则 + 应用服务（search/announcement/home/dashboard）
├── modules/             蓝图视图（只做参数解析、调用服务、渲染/提示）
├── forms/               WTForms 表单（autocomplete/aria 等可访问性属性）
└── utils/               constants / contracts / table_driven / pinyin / time_slots / pagination
```

新增 `wsgi.py` 作为生产服务器入口；`run.py` 保留原有命令行参数以兼容课程文档。

## 4. 代码优化清单

| 优化 | 位置 | 说明 |
| --- | --- | --- |
| 时段解析单一事实来源 | `app/utils/time_slots.py` | `parse_slot` 统一格式/范围/先后校验，`is_slot_started/ended` 只做比较 |
| 应用服务层 | `services/search_service.py` 等 | 关键词超长、分类/排序白名单、空结果提示从视图收回 |
| 消除 N+1 | `ServiceRepository.counts_by_category`、`AppointmentRepository.list_reviewable_by_user` | 一次 GROUP BY / NOT EXISTS 代替逐条查询 |
| 分页与状态白名单 | `app/utils/pagination.py` | `page=0/abc`、非法状态不再进入查询 |
| 数据规范化 | `User`、`ServiceItem` 的 `@validates` | 邮箱小写、用户名/服务名去空白，拼音键随名称同步 |
| 重名校验 | `ServiceRepository.name_conflict` | 编辑服务时排除自身，避免唯一约束 500 |
| 会话安全 | `user_loader`、`config.py` | 禁用/删除账号的旧会话立即失效；Cookie HttpOnly+SameSite |
| 统一错误页 | `app/errors.py` + `errors/error.html` | 400/403/404/405/413/500 同一版式，5xx 不泄露堆栈 |
| 可观测性 | `app/logging.py` | 每请求 `X-Request-ID`，访问日志含方法/路径/状态/耗时 |
| 前端安全 | 模板去内联样式 + CSP | `style-src 'self'`，不再需要 `unsafe-inline` |
| 可访问性 | `base.html`、表单 | skip link、`aria-live`、`autocomplete`、`inputmode` |

## 8. 后续建议

1. 引入 Flask-Migrate/Alembic，把 `db.create_all()` 升级为可回滚的版本化迁移；
2. 生产部署使用 Gunicorn/waitress + Nginx + MySQL 8.0，并开启 HTTPS/HSTS；
3. 为管理员写操作增加审计日志表（谁在何时改了哪条记录）；
4. 把 Locust 压测与兼容性检查纳入夜间任务，而不是只保留报告；
5. 若后续引入 API，复用同一套错误码与 request_id，避免 Web/API 两套错误语义。
