# Git 提交规范

## 提交信息格式
```
<type>(<scope>): <本次增量完成的简短说明>
```
- **type**：feat（新功能）/ refactor（重构）/ test（测试）/ docs（文档）/ fix（缺陷修复）/ chore（环境配置）
- **scope**：模块名，如 auth、appointment、service、admin、docs

## 约定
1. 一次提交只做一件事（对应一个用户故事或一次重构）；
2. 每个实验（增量）结束时必须提交，保证历史连贯可追溯；
3. 测试未通过不允许提交；
4. 提交正文（可选）写清"为什么改"与"影响范围"。

## 本项目提交历史（示例）

| # | 提交 | 对应实验 |
| --- | --- | --- |
| 1 | `chore(project): 初始化Flask项目骨架与Git仓库` | 实验一 |
| 2 | `feat(appointment): 以TDD方式构造预约管理核心模块` | 实验二 |
| 3 | `feat(models): 领域模型、数据库表结构与数据访问层` | 实验三 |
| 4 | `feat(web): 页面、表单、会话管理与集成测试` | 实验四 |
| 5 | `refactor: 代码重构、系统集成与交付文档` | 实验五 |
