# 部署与运行说明

## 1. 运行环境

| 项目 | 要求 | 本机实测 |
| --- | --- | --- |
| 操作系统 | Windows 10/11 / Linux | Windows 11 |
| Python | 3.10+ | **Python 3.12**（`D:\Download\pythonContent\python.exe`） |
| 浏览器 | Chrome / Edge / Firefox | Chrome |
| 数据库 | SQLite（默认）或 MySQL 8.0 | SQLite（`instance/app.db`） |
| 磁盘 | ≥ 50 MB | — |

## 2. 安装与启动（4 步）

```bash
# ① 安装依赖（开发/测试再加 ruff）
pip install -r requirements.txt
# pip install -r requirements-dev.txt

# ② 建库 + 写入演示数据（幂等，绝不删除已有数据）
python run.py --init-db --seed

# ③ 启动应用
python run.py

# ④ 浏览器访问
#    http://127.0.0.1:5000
```

默认账号：

| 角色 | 用户名 | 密码 |
| --- | --- | --- |
| 管理员 | `admin` | `Admin@123` |
| 普通用户 | `zhangsan` | `User@123` |

> 若不想写入演示数据，只执行 `python run.py --init-db` 即可，然后自行注册账号；
> 也可以 `flask --app "app:create_app()" create-admin <username> <email>`
> 创建管理员（密码交互输入，复用同一套密码策略）。
>
> ⚠️ **数据安全**：`--init-db` / `--seed` 均为幂等操作，`create_all()` 只建缺失的表，
> `seed_demo_data()` 只补同名缺失记录，**都不会删除任何已有数据**，可放心重复执行。
> 2026-11-23 前的旧版本会在初始化时无条件 `db.drop_all()`，曾导致真实数据被清空两次，已修复。
> 若确实需要清空重建，必须显式传 `--force-reset`：
> ```bash
> python run.py --init-db --seed --force-reset   # 会打印将删除的各表行数，操作不可恢复
> ```
> 执行前请务必先备份 `instance/app.db`。

## 3. 常用命令

```bash
# 开发/初始化
python run.py --config development          # 开发环境（默认）
python run.py --config testing              # 测试环境（内存数据库）
python run.py --host 0.0.0.0 --port 8080    # 指定监听地址与端口

# Flask CLI（推荐，与应用同配置）
flask --app "app:create_app()" init-db
flask --app "app:create_app()" seed-demo
flask --app "app:create_app()" check-db     # 连接/表结构/行数自检
flask --app "app:create_app()" create-admin boss boss@example.com

# 数据库版本化（生产/升级）
flask --app "app:create_app()" db upgrade
flask --app "app:create_app()" db migrate -m "描述本次结构变更"

# 测试与质量门禁
pytest                                      # 全部测试（569 条）
pytest -m unit                              # 按层执行：unit/functional/integration/system
pytest --cov=app --cov-branch --cov-report=html
python -m ruff check app tests scripts run.py seed.py wsgi.py
python scripts/static_check.py              # 静态程序分析（教材 5.4.7）
python scripts/generate_schema.py           # 导出数据库脚本 docs/schema.sql
```

## 4. 生产部署

生产依赖、Nginx、systemd、迁移与审计的完整说明见 `docs/16-生产部署与数据库迁移.md`，
示例配置在 `deploy/`。最短路径：

```bash
pip install -r requirements-prod.txt

# 生产必须设置随机 SECRET_KEY；数据库先用迁移建好
export SECRET_KEY="$(python -c 'import secrets;print(secrets.token_hex(32))')"
export FLASK_CONFIG=production
export DATABASE_URL="mysql+pymysql://user:password@127.0.0.1:3306/convenience?charset=utf8mb4"
flask --app "app:create_app" db upgrade
flask --app "app:create_app" check-db

gunicorn -c deploy/gunicorn.conf.py wsgi:app
# 或 systemd：先用 deploy/render_configs.py 渲染，再安装生成的 service
```

已有 SQLite 库升级到带审计表的版本时**不要直接 upgrade**：
先备份，再按 `docs/16` 第 1.2 节执行 `db stamp 7c0a74a1027b` + `db upgrade`，
或先 `python run.py --init-db` 补表后 `db stamp head`。

生产配置默认开启 `SESSION_COOKIE_SECURE` / `REMEMBER_COOKIE_SECURE`；
HTTPS 请求会追加 HSTS。建议前置 Nginx 处理 TLS 与静态资源，并配置日志轮转。
健康检查：`GET /healthz`（数据库不可用时返回 503）。

## 5. 日志与可观测性

| 项目 | 说明 |
| --- | --- |
| 日志位置 | `instance/logs/app.log`（按 2 MB × 5 份滚动） |
| 日志级别 | `LOG_LEVEL` 环境变量，默认 INFO；测试环境 WARNING 且不写文件 |
| 请求追踪 | 每个请求生成/透传 `X-Request-ID`，响应头返回；日志行带同一 ID |
| 访问日志 | 方法、路径、状态码、耗时（静态资源不记访问日志） |
| 5xx | 统一错误页 + 带堆栈的 ERROR 日志，页面不泄露异常细节 |

## 7. 常见问题

| 问题 | 原因 | 处理 |
| --- | --- | --- |
| 页面提示"请先登录" | 未登录访问受限页面 | 登录后会自动跳回原页面 |
| 访问 `/admin/` 报 403 | 当前账号不是管理员 | 用 `admin` 账号登录 |
| 修改代码后页面没变 | 浏览器缓存 | Ctrl+F5 强制刷新 |
| 提示 `no such table` | 未初始化数据库 | 执行 `python run.py --init-db --seed` |
| 端口被占用 | 5000 端口已占用 | `python run.py --port 5001` |
| 生产启动报 SECRET_KEY 错误 | 未设置环境变量 | 按第 4 节设置随机 `SECRET_KEY` |
| 表单提交返回 400 | CSRF 令牌缺失/过期 | 刷新页面重新提交（不要直接复用旧表单） |
| `flask db upgrade` 报表已存在 | 旧库没有 alembic 版本标记 | 先备份，按 `docs/16` 第 1.2 节 `db stamp 7c0a74a1027b` 后再 upgrade |
| 审计页面提示表不存在 | 旧库未执行审计表迁移 | `python run.py --init-db`（只补表）或按 `docs/16` 执行迁移 |
